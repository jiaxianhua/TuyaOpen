# 字符计数机制详解 / Character Counting Mechanism Explained

## 问题：为什么 CHARS_PER_LINE = 37？

你可能注意到了这个看似矛盾的定义：

```c
#define CHARS_PER_LINE 37   // 注释说：480 / 24 ≈ 20 个中文字符
#define LINES_PER_PAGE 32   // 注释说：800 / 24 ≈ 33 行
```

**疑问**：
- 480 / 24 = 20，为什么是 37？
- 800 / 24 = 33.3，为什么是 32？

## 答案：字符单位 vs 像素

### 关键概念

`CHARS_PER_LINE` **不是像素数**，而是**字符单位数**！

代码中使用了一个巧妙的计数系统：

```c
int char_width = (char_len == 2) ? 2 : 1;  // GBK=2单位, ASCII=1单位
```

### 字符单位系统

| 字符类型 | 字节数 | 像素宽度 | 字符单位 |
|---------|--------|----------|----------|
| ASCII (英文) | 1 字节 | 12 像素 | 1 单位 |
| GBK (中文) | 2 字节 | 24 像素 | 2 单位 |

### 为什么这样设计？

因为文本是**中英文混排**的！

#### 示例 1：纯中文

```
屏幕宽度：480 像素（逻辑，竖屏）
中文字符：24 像素宽
可容纳：480 / 24 = 20 个中文字符
字符单位：20 个中文 × 2 单位 = 40 单位
```

#### 示例 2：纯英文

```
屏幕宽度：480 像素
英文字符：12 像素宽
可容纳：480 / 12 = 40 个英文字符
字符单位：40 个英文 × 1 单位 = 40 单位
```

#### 示例 3：混合文本

```
文本："Hello你好World世界"
分解：
- "Hello" = 5 个英文 = 5 单位 = 60 像素
- "你好" = 2 个中文 = 4 单位 = 48 像素
- "World" = 5 个英文 = 5 单位 = 60 像素
- "世界" = 2 个中文 = 4 单位 = 48 像素
总计：18 单位 = 216 像素
```

## 实际计算

### CHARS_PER_LINE = 37

```
逻辑屏幕宽度：480 像素（ROTATE_90 后）
左边距：10 像素
可用宽度：470 像素

纯中文情况：
470 / 24 = 19.58 ≈ 19 个中文字符
19 × 2 = 38 单位

纯英文情况：
470 / 12 = 39.16 ≈ 39 个英文字符
39 × 1 = 39 单位

取中间值：37 单位
```

**为什么是 37 而不是 40？**
- 考虑了左边距（10 像素）
- 考虑了右边距（留白）
- 37 单位可以容纳：
  - 18-19 个中文字符（36-38 单位）
  - 或 37 个英文字符（37 单位）
  - 或混合文本

### LINES_PER_PAGE = 32

```
逻辑屏幕高度：800 像素（ROTATE_90 后）
字符高度：24 像素
理论行数：800 / 24 = 33.3 行

实际设置：32 行

原因：
- 顶部有标题栏（24 像素）
- 底部留白
- 800 - 24 = 776 像素
- 776 / 24 = 32.3 ≈ 32 行
```

## 代码实现

### 1. 计算字符宽度

```c
int char_len = get_char_byte_len(g_reader_ctx.content, pos, content_len);
int char_width = (char_len == 2) ? 2 : 1;  // GBK=2单位, ASCII=1单位
```

### 2. 检查是否超出行宽

```c
if (line_width + char_width > CHARS_PER_LINE && line_width > 0) {
    break;  // 行满，换行
}
```

### 3. 累加字符单位

```c
line_width += char_width;  // 累加单位数，不是像素数
```

### 4. 绘制时使用实际像素

```c
if (c < 0x80) {
    // ASCII: 12 像素宽
    Paint_DrawString_EN(x_pos, y_pos, ascii_str, &Font24, BLACK, WHITE);
    x_pos += 12;
} else {
    // GBK: 24 像素宽
    draw_gbk_char24(x_pos, y_pos, gb_high, gb_low, BLACK, WHITE);
    x_pos += 24;
}
```

## 为什么显示是全屏的？

因为 37 单位的设计恰好能充分利用屏幕空间：

### 纯中文文本

```
37 单位 / 2 = 18.5 ≈ 18 个中文字符
18 × 24 像素 = 432 像素
加上左边距 10 像素 = 442 像素
屏幕宽度 480 像素
利用率：442 / 480 = 92%
```

### 纯英文文本

```
37 单位 = 37 个英文字符
37 × 12 像素 = 444 像素
加上左边距 10 像素 = 454 像素
屏幕宽度 480 像素
利用率：454 / 480 = 94.6%
```

### 混合文本（最常见）

```
假设：10 个中文 + 17 个英文
10 × 2 + 17 × 1 = 37 单位
10 × 24 + 17 × 12 = 240 + 204 = 444 像素
加上左边距 10 像素 = 454 像素
利用率：94.6%
```

```
行内容："第一章 山边小村"
字符分解：
- "第" = 2 字节 = 2 单位 = 24 像素
- "一" = 2 字节 = 2 单位 = 24 像素
- "章" = 2 字节 = 2 单位 = 24 像素
- " "  = 1 字节 = 1 单位 = 12 像素
- "山" = 2 字节 = 2 单位 = 24 像素

```

## 总结

1. **CHARS_PER_LINE = 37** 是**字符单位数**，不是像素数
2. **字符单位系统**：
   - ASCII = 1 单位 = 12 像素
   - GBK = 2 单位 = 24 像素
3. **设计目的**：支持中英文混排
4. **屏幕利用率**：约 92-95%
5. **LINES_PER_PAGE = 32**：考虑了标题栏和底部留白

## 如何修改？

### 增加每行字符数

```c
// 增加到 40 单位（更紧凑）
#define CHARS_PER_LINE 40

// 结果：
// - 纯中文：20 个字符（480 像素，100% 利用率）
// - 纯英文：40 个字符（480 像素，100% 利用率）
```

### 减少每行字符数

```c
// 减少到 34 单位（更宽松）
#define CHARS_PER_LINE 34

// 结果：
// - 纯中文：17 个字符（408 像素，85% 利用率）
// - 纯英文：34 个字符（408 像素，85% 利用率）
```

### 增加每页行数

```c
// 增加到 33 行（更紧凑）
#define LINES_PER_PAGE 33

// 结果：
// - 33 × 24 = 792 像素
// - 加上标题 24 像素 = 816 像素（超出 800 像素！）
// - 不推荐，会导致底部文字被截断
```

## 调试技巧

### 打印字符单位信息

```c
PR_DEBUG("Line: '%s', units=%d, pixels=%d", 
         line_buf, line_width, actual_pixel_width);
```

### 验证屏幕利用率

```c
int total_pixels = 0;
for (int i = 0; i < line_len; i++) {
    if (is_gbk_lead_byte(line_buf[i])) {
        total_pixels += 24;
        i++;  // Skip next byte
    } else {
        total_pixels += 12;
    }
}
PR_DEBUG("Screen utilization: %d / 480 = %.1f%%", 
         total_pixels, (total_pixels * 100.0) / 480);
```
