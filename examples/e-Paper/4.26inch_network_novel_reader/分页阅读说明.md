# 分页阅读功能说明

## 问题

之前尝试打开 10.8 MB 的小说文件时，出现内存分配失败：

```
tkl_system_malloc failed, size(10840335)!
malloc failed:0xa5690f free:0x2a8e0
```

设备只有约 170 KB 的可用内存，无法一次性加载整个文件。

## 解决方案

实现了**分页阅读**功能，每次只读取 1KB 的内容，而不是一次性加载整个文件。

## 工作原理

### 1. 打开文件时

```
文件大小: 10,840,334 字节 (10.8 MB)
页面大小: 1,024 字节 (1 KB)
总页数: 10,586 页
```

系统只计算页数，不加载文件内容。

### 2. 显示页面时

每次显示页面时，动态加载当前页：

```
第 1 页: 读取字节 0-1023
第 2 页: 读取字节 1024-2047
第 3 页: 读取字节 2048-3071
...
```

### 3. 翻页时

- **单击按钮**: 释放当前页，加载下一页
- **双击按钮**: 释放当前页，加载上一页

## 内存使用对比

### 之前（失败）

```
需要内存: 10,840,335 字节 (10.34 MB)
可用内存: 175,328 字节 (171 KB)
结果: 内存分配失败 ❌
```

### 现在（成功）

```
需要内存: 1,024 字节 (1 KB)
可用内存: 175,328 字节 (171 KB)
结果: 成功 ✅
```

## 使用方法

1. 将大文件（如 `doupocangqiong.txt`）复制到 SD 卡
2. 在文件浏览器中选择文件
3. 长按按钮打开文件
4. 单击翻到下一页，双击翻到上一页

## 技术细节

### 新增函数

1. **`sd_get_page_count()`** - 计算文件总页数
2. **`sd_read_text_page()`** - 读取指定页面
3. **`load_page_from_file()`** - 动态加载页面

### 修改的结构

```c
typedef struct {
    char current_filepath[300];  // 当前文件路径
    int use_paged_reading;       // 是否使用分页阅读
    int page_size;               // 每页字节数（1024）
} novel_reader_ctx_t;
```

### 两种模式

#### 内存模式（小文件）

- 网络下载的小说
- 内置小说
- 小于 1MB 的文件

特点：整个内容在内存中，翻页快速

#### 分页模式（大文件）

- SD 卡上的大文件
- 大于 1MB 的文件

特点：只有当前页在内存中，节省内存

## 配置

### 页面大小

当前设置为 **1KB**（1024 字节）：

```c
g_reader_ctx.page_size = 1024;  // 每页 1KB
```

可以根据需要调整：

- **更小** (512 字节): 更多页数，更少内存，更频繁的文件读取
- **更大** (2048 字节): 更少页数，更多内存，更少的文件读取

### 显示容量

每屏可以显示：

- **每页行数**: 32 行
- **每行字符**: 38 个单位（约 19 个汉字）
- **大约文本**: 每屏 600-800 字节

1KB 的页面大小略大于一屏内容，确保翻页流畅。

## 优点

✅ **节省内存**: 每次只占用 1KB 内存  
✅ **支持大文件**: 可以处理任意大小的文件  
✅ **启动快速**: 无需等待加载整个文件  
✅ **稳定可靠**: 不会出现内存分配失败  

## 注意事项

⚠️ **翻页速度**: 每次翻页需要读取文件，可能比内存模式稍慢  
⚠️ **页面边界**: 按字节分页，可能在汉字中间断开（显示时会处理）
